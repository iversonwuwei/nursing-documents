# 完整契约文档：排班更新

## 契约目标

定义排班更新接口的入参、冲突规则、失败模式和回滚路径，保障人工调班可控。

## 接口定义

- 方法: `PUT`
- 路径: `/api/staff/schedule/:scheduleId`
- 调用方: 排班管理页、主管调班弹层

## 路径契约

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| scheduleId | string | 是 | 排班记录 ID |

## 请求体契约

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| staffId | string | 是 | 员工 ID | 被调整员工 |
| shift | string | 是 | 枚举 | `早班`、`中班`、`夜班`、`休息` |
| date | string | 是 | 日期字符串 | 排班日期 |
| remark | string | 否 | 最长 200 字符 | 调整原因 |

## 响应契约

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| success | boolean | 是 | 是否更新成功 |
| scheduleId | string | 是 | 排班记录 ID |
| updatedAt | string | 是 | 更新时间 |
| conflictHint | string | 否 | 冲突提示 |

## 冲突规则

- 同一员工同一天只能有一条有效排班。
- 超过锁定时间窗的班次不可修改。
- 关键岗位缺班需额外人工确认。

## 幂等性

- 对同一 `scheduleId` 提交完全相同的更新请求，应视为幂等成功。
- 若内容发生变化，则视为新的排班变更。

## 兼容性策略

- `shift` 新增枚举前需同步页面字典和颜色映射。
- `remark` 可为空，前端需兼容无备注情况。

## 失败模式

- 参数缺失 `400`
- 记录不存在 `404`
- 排班冲突 `409`
- 保存失败 `500`

## 可观测性

- 建议日志字段: `scheduleId`、`staffId`、`shift`、`date`
- 建议指标: 更新成功率、冲突率、回滚率

## 回滚说明

如接口写入链路不稳定，可回退为只读排班展示，并改由线下或后台人工维护。
