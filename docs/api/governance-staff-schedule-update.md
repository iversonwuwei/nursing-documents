# 治理级文档：排班更新

## 范围

面向排班管理页和主管调班弹层，定义排班更新接口的冲突治理、审计要求和回滚策略。

## 入口与调用方

- 方法: `PUT`
- 路径: `/api/staff/schedule/:scheduleId`
- 主要调用方: 排班管理页、主管调班弹层
- 发布阶段: 先护理主管角色，再扩展到机构管理员

## 依赖边界

- 主数据源: 排班记录表
- 扩展依赖: 员工档案、岗位规则、班次锁定窗口
- 风险点: 写操作会直接影响实际班次安排

## 成功判据

- 同一员工同一天只能存在一条有效排班
- 关键岗位缺班冲突可被明确拦截
- 调班结果能在列表与日志中同步可见

## 运行健康信号

- SLI: `p95_latency < 500ms`
- SLI: 成功率 `>= 99.0%`
- 业务指标: 冲突识别准确率 `= 100%`
- 业务指标: 重复写入率 `< 0.1%`

## 失败模式

- `400`: 参数不合法
- `404`: 排班记录不存在
- `409`: 排班冲突或锁定窗口内不可编辑
- `500`: 写入失败
- 降级策略: 排班页切换为只读模式，保留人工审批记录

## 日志与监控

- 结构化日志字段: `scheduleId`、`staffId`、`shift`、`date`、`conflict`、`operatorId`
- 监控图表: 更新成功率、冲突率、回滚率、重复提交率
- 告警建议: 15 分钟内冲突率异常升高或写入失败率超过 1% 时触发 P1 告警

## 兼容性策略

- 班次枚举新增前需同步页面字典、颜色和审批规则
- `remark` 允许为空
- 幂等重复提交必须返回稳定结果

## 验证门禁

- 契约测试覆盖正常更新、冲突、锁定窗口、重复提交
- 页面联调验证更新后列表刷新与审计记录同步
- 发布前检查主管角色权限和操作审计链路

## 回滚路径

1. 关闭写接口，仅保留排班只读展示。
2. 调班改为线下审批或后台人工处理。
3. 保留历史审计记录，待链路稳定后再恢复写入。
