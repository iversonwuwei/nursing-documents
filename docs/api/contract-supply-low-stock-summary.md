# 完整契约文档：低库存摘要查询

## 契约目标

为物资列表页、补货摘要卡片和 AI 补货建议提供一致的库存缺口数据。

## 接口定义

- 方法: `GET`
- 路径: `/api/supplies/low-stock-summary`
- 调用方: 物资列表页、报表中心、AI 运营中心

## 请求契约

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| category | string | 否 | 文本 | 物资分类 |
| urgentOnly | boolean | 否 | 布尔值 | 是否只返回高优先级物资 |

## 响应契约

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| lowStockCount | number | 是 | 低库存物资数 |
| totalGap | number | 是 | 总缺口 |
| topSupply | object | 否 | 最紧急物资 |
| topSupply.id | string | 是 | 物资 ID |
| topSupply.name | string | 是 | 物资名称 |
| topSupply.gap | number | 是 | 当前缺口 |

## 状态流

1. 页面加载低库存摘要。
2. 服务按分类或紧急优先过滤。
3. 返回低库存数量、总缺口和最紧急物资。
4. 页面据此渲染 AI 补货摘要与跟进入口。

## 兼容性策略

- `topSupply` 允许为空，前端需兼容无最紧急物资场景。
- `totalGap` 语义固定为安全库存差额总和，不应改成其他统计口径。

## 失败模式

- `400`: 参数非法
- `500`: 低库存摘要查询失败

## 可观测性

- 建议日志字段: `category`、`urgentOnly`
- 建议指标: 低库存数量、摘要查询成功率、平均缺口规模

## 回滚说明

如摘要接口异常，可回退为页面端基于物资列表自行计算低库存数量与缺口。
