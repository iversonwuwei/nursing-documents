# 流程级文档：管理端新建数据闭环

## 场景目标

把 admin 端“新增老人”等新建动作从单页录入改造成可追踪、可审核、可同步下游的治理闭环，避免出现“表单已提交，但任务、提醒和主台账没有跟上”的断层。

## 主流程

1. 用户从老人列表页进入新增老人页。
2. 页面录入首批最小可执行字段集：姓名、年龄、性别、联系电话、房间、紧急联系人、ADL、认知状态和风险备注。
3. 提交后写入共享 workflow store，并立即生成 AI 护理等级建议、风险标签和护理模板编码。
4. 系统跳转到入住审核页，并自动定位到刚创建的申请记录。
5. 护理主管确认或调整护理等级；若调整，必须补充人工说明。
6. 系统生成首批护理计划，并同步派生员工任务与提醒中心数据。
7. 主管将记录标记为已入住后，该对象进入老人列表与详情页的统一台账。

## 分支流程

### 表单校验失败

1. 页面保留输入内容。
2. 以表单级错误提示阻止提交。
3. 用户修正后重新提交。

### AI 建议与人工判断不一致

1. 护理主管修改最终护理等级。
2. 页面要求填写调整说明。
3. 计划与提醒按人工确认结果生成，而不是按 AI 默认值生成。

### 已创建但尚未入住

1. 记录先以待入住口径进入老人台账。
2. 列表页展示其处于新建闭环中。
3. 详情页继续展示当前申请态，直到入住确认完成。

## 适用实体

- 老人：录入 -> 评估 -> 计划 -> 在住
- 机构：录入 -> 资质校验 -> 容量生效 -> 列表可承接
- 房间：录入 -> 床位配置 -> 排房可用 -> 列表可入住
- 活动：录入 -> 审核排期 -> 通知同步 -> 活动台账

## 埋点建议

- `admin_create_entry_clicked`
- `elderly_create_submitted`
- `elderly_checkin_review_confirmed`
- `elderly_checkin_marked_admitted`

## 测试清单

- 新增老人提交后必须跳转到带 `selected` 参数的入住审核页
- 入住审核页必须自动选中新建记录
- 人工确认后员工任务页和提醒中心页可看到派生数据
- 标记已入住后老人列表与详情页可看到同一对象
