# 护理页交付说明

## 范围

- 变更名称：护理页交付说明补齐与反馈入口锚点
- 页面或路由入口：根 Tab “护理”
- 影响用户：查看护理执行记录和提交家属反馈的用户
- 发布阶段：原型工程内默认开启

## 用户影响

- 护理页继续承担护理记录、执行状态和 AI 护理说明的聚合展示。
- “提交护理反馈”入口现在具备稳定锚点，可验证护理页到反馈页的跳转链路。
- 不变行为：护理记录仍是只读原型数据，不引入实时执行回执或家属评论流。

## 数据或 Mock 来源

- 当前数据来源：`MockFamilyService.todayCareRecords`
- 当前边界：展示家属可见护理摘要，不包含内部护理站操作明细
- 后续替换路径：可由护理执行服务或 BFF 替换 `MockFamilyService`

## UI 状态

- 加载态：当前为本地 Mock，同步渲染
- 空态：当前未拆分护理记录空态，后续接真实接口时需补齐
- 错误态：当前无远程请求，仍以原型展示为主
- 手机端影响：保留纵向时间线卡片和说明卡布局

## 可观测性与健康信号

- 健康信号：护理页可进入、记录卡可见、反馈入口可跳转
- 失败信号：护理记录缺失、说明卡不可见、反馈入口无法打开
- 稳定验证锚点：护理页反馈入口 key

## 验证门禁

- 必跑：`flutter analyze`
- 必跑：`flutter test`
- 建议手工验证：从护理页进入护理反馈并返回

## 回滚

- 可直接回退到无稳定锚点的原始实现
- 不涉及路由、权限或数据迁移，回滚成本低

## 风险与未验证项

- 已知风险：当前未覆盖真实护理状态回流、排序和接口失败场景
- 未验证项：未接入真实护理任务链路和家属反馈回执
