# 报警历史页交付说明

## 范围

- 变更名称：家属端报警历史页等级筛选与空态兜底
- 页面或路由入口：`/alertHistory`
- 影响用户：从“我的服务”进入报警历史的家属端用户
- 发布阶段：原型工程内默认开启

## 用户影响

- 用户现在可以按报警等级查看异常事件，而不是只能浏览静态历史列表。
- 当某一等级下无记录或全量无记录时，页面会给出稳定空态和恢复入口。
- 不变行为：页面仍然是历史只读视图，不引入家属端确认、闭环或复核操作。

## 数据或 Mock 来源

- 当前数据来源：`MockFamilyService.alerts`
- 当前边界：只展示家属可见的事件摘要，不引入护理站内部处置细节
- 后续替换路径：可由 BFF 或正式告警事件服务替换 `MockFamilyService`

## UI 状态

- 加载态：当前为本地 Mock，同步渲染，不单独展示骨架屏
- 空态：新增“当前没有报警记录”卡片，并支持切回全部等级
- 错误态：当前无远程请求，保持只读提示兜底
- 手机端影响：维持单列事件卡片，不引入更高交互复杂度

## 页面状态稳定性

- 等级筛选使用页面内状态，不影响根壳或其他页签状态
- 重新进入页面时默认回到“全部”，优先保持可预测行为
- 事件排序按时间倒序，优先暴露最新异常记录

## 可观测性与健康信号

- 健康信号：页面可进入、最新时间显示正常、等级筛选可切换、空态可恢复
- 失败信号：页面白屏、筛选切换不生效、最新记录排序错误、空态不可恢复
- 稳定验证锚点：报警卡片 key、筛选 key、空态 key

## 验证门禁

- 必跑：`flutter analyze`
- 必跑：`flutter test`
- 建议手工验证：从“我的服务”进入报警历史页，切换等级并确认列表变化

## 回滚

- 可直接回退到无筛选的原始历史列表实现
- 若后续真实事件链路不稳定，可继续保留当前只读历史模式
- 不涉及路由、权限或数据迁移，回滚成本低

## 风险与未验证项

- 已知风险：当前排序依赖原型时间字符串可以转换成 `DateTime`
- 未验证项：未接入真实告警状态流转、确认回执和分页加载
