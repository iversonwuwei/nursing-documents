# 消息页交付说明

## 范围

- 变更名称：家属端消息页筛选与空态兜底
- 页面或路由入口：`/messages`
- 影响用户：从首页快捷入口或“我的服务”进入消息中心的家属端用户
- 发布阶段：原型工程内默认开启

## 用户影响

- 用户现在可以按分类查看消息，而不是只能浏览静态全量列表。
- 当消息为空或某个分类下无数据时，页面会展示稳定空态，而不是保留空白列表或依赖隐式行为。
- 不变行为：消息中心仍然是只读展示，不引入真实下拉刷新、已读状态或服务端回执。

## 数据或 Mock 来源

- 当前数据来源：`MockFamilyService.notifications`
- 当前边界：只展示家属可见提醒，不引入员工侧事件明细或管理后台字段
- 后续替换路径：可由 BFF 或真实 API Repository 替换 `MockFamilyService`

## UI 状态

- 加载态：当前为本地 Mock，同步进入页面，不单独展示骨架屏
- 空态：页面新增“当前没有新消息”卡片，并支持一键切回“全部”分类
- 错误态：当前没有网络请求，错误态仍以数据缺失兜底为主
- 手机端影响：沿用现有单列卡片布局，不改变家属端手机优先布局

## 页面状态稳定性

- 分类筛选使用页面内状态，不影响主 Tab Shell 的 IndexedStack 保持策略
- 返回后是否保留筛选状态：当前不做跨路由持久化，重新进入页面回到“全部”分类
- 这样做的原因：当前阶段优先保证行为可预测和测试可覆盖，避免引入额外状态同步复杂度

## 可观测性与健康信号

- 健康信号：页面可进入、默认展示消息驾驶舱、分类筛选可切换、空态可见且可恢复到全部分类
- 失败信号：页面白屏、首屏因空数据崩溃、筛选切换后列表不更新、空态不可恢复
- 稳定验证锚点：消息卡片 key、筛选 key、空态 key

## 验证门禁

- 必跑：`flutter analyze`
- 必跑：`flutter test`
- 建议手工验证：从首页和“我的服务”两条入口进入消息页，切换“探视”等分类并验证列表变化

## 回滚

- 可直接回退到无筛选的静态列表实现
- 若后续真实接口不稳定，可保持当前只读 Mock 展示模式
- 不涉及路由、权限或数据迁移，回滚成本低

## 风险与未验证项

- 已知风险：当前时间排序规则只覆盖“刚刚”、“HH:mm”和“昨天”这类原型数据格式
- 未验证项：未接入真实消息已读状态、推送时序和分页行为
