# 页面级文档：Dashboard 首页

## 交付模板

- scope: 以首页作为 Fluent 2 风格试点，把根路由进一步收敛为“运营优先级入口”，主区只保留总览、优先动作和专页下钻，移除首页内的 AI 摘要、趋势图和分析型块。
- affected users: 管理员、机构负责人、日班值守人员。
- changed behavior: 首页继续读取 Admin BFF 聚合快照，但不再试图同时承担分析页；AI 解释、趋势观察和细项执行统一退回 AI 中心、健康监测、任务与专门工作台页面。
- dependent systems: Admin BFF、Admission workflow store、SaaS session/platform state。
- verification: `npm run docs:build`、admin 前端 `npm run lint` 与 `npm run build`；手工检查 `/` 首屏只剩优先级入口闭环。
- rollback: 回退首页布局和文档到当前版本；不涉及服务契约、写接口或数据迁移回滚。

## 页面目标

让管理者在登录后 10 秒内完成两件事：先判断今天最需要处理什么，再决定进入哪个专页或工作台。首页不是分析页，也不是执行页。

## 主要区块

- 总览卡：展示聚合快照、待办压力和关键健康信号。
- 今日优先动作：把告警、认定、护理执行和经营收口变成可立即下钻的入口卡。
- 专页下钻入口：明确把任务、健康、告警等执行逻辑退回对应页面。
- 轻量快捷入口：保留高频导航，但不再和解释性模块混排。
- 后置上下文区：只保留视角切换、来源状态、租户模块摘要和帮助入口。

## 数据来源

- 首页聚合快照: `/api/dashboard/overview` -> Admin BFF `/api/admin/dashboard/overview`
- 本地只读补位: `equipmentAlarms`、Admission workflow snapshot、租户模块 session state
- 说明边界: AI insight 与趋势图不再作为首页事实源；需要进一步解释时跳转到 AI 或专门分析页。

## 状态设计

- 加载态: 总览卡和关键 KPI 进入 `Syncing`，动作入口保持可点，但需要明确提示聚合仍在同步。
- 空态: 当首页没有高优先级积压时，仍保留优先动作卡并给出“当前无积压，可进入常规巡检”的提示。
- 错误态: 聚合失败时显示 `Live Unavailable`，允许继续跳转到专页，不回退到分析型假数据块。
- 移动端: 继续维持纵向堆叠；Fluent 试点下不允许恢复双栏，也不允许趋势图类块造成纵向滚动噪音。

## 风险边界

- 首页只负责定优先级和路由分流，不重新引入任务表、健康明细、AI 长摘要或经营趋势图。
- Fluent 试点只改共享样式和首页编排，不引入新的设计系统依赖，也不修改 Next 路由结构。
- 如果聚合口径暂时不足，优先减少首页内容，而不是回填不可验证的装饰型模块。
