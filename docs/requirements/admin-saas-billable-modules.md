# Admin SaaS 业务模块订阅

## Scope

- scope: 把 nursing-admin-v2 的 SaaS 模块划分从端能力切换为业务模块能力，使系统可以按业务模块订阅、交付和收费。
- affected users: 平台销售、租户管理员、实施顾问、超级管理员、机构管理员。
- changed behavior: 顶层导航与首页入口改为优先表达可计费业务模块；租户未开通的模块不应继续在主导航中暴露；机构养老与居家养老场景继续保留，但下沉到模块内部承接。
- dependent systems: admin 登录态、tenant entitlements、顶部导航、Dashboard 首页、AI 入口与后续模块页禁用态。
- verification: nursing-documents `npm run docs:build`；nursing-admin-v2 `npm run lint`、`npm run build`。
- rollback: 回退业务模块 entitlement 映射、顶部导航分组、首页订阅模块视图和相关文档入口。

## 目标

- 让租户套餐表达从“admin/family/nani”切到“报警服务/财务服务/通知服务/长护险业务/AI 运营”等业务模块。
- 保持机构养老与居家养老两条场景线，但它们不再作为唯一的顶层收费单元，而是作为业务模块内部的场景入口。
- 让平台能清晰回答三个问题：租户买了哪些模块、模块入口在哪里、未购买模块如何被隐藏或禁用。

## 模块划分

| 业务模块 | 主要入口 | 收费口径示例 | 说明 |
| --- | --- | --- | --- |
| 首页概览 | `/`、`/operations/daily` | 基础管理席位 | 作为基础管理工作台，不再承载其他业务模块收费逻辑 |
| 长者照护 | `/elderly`、`/elderly/new`、`/elderly/face`、`/staff?scene=home` | 在住老人规模 / 协同照护席位 | 内部继续区分机构养老与居家养老场景 |
| 健康设备 | `/health`、`/devices`、`/devices/realtime` | 设备数 / 监测点位 | 统一承接健康监测与设备监控 |
| 报警服务 | `/alerts`、`/alerts/history`、`/incidents` | 活跃监测对象 / 事件量 | 承接紧急呼叫、离床预警、异常预警、SOS 处置 |
| 评定与长护险 | `/elderly/checkin`、`/staff/tasks`、`/staff/schedule`、`/nursing/packages`、`/nursing/plans` | 认定单量 / 服务包 | 场景差异仍通过 `scene` 承接 |
| 财务服务 | `/financial` | 账单量 / 结算量 | 承接费用计算、账单生成、欠费预警、票据归档 |
| 通知服务 | `/notifications` | 发送量 / 通道包 | 承接短信推送、探视通知、定时提醒、公告广播 |
| 机构协同 | `/organizations`、`/branch`、`/rooms`、`/supplies` | 机构数 / 院区数 | 承接机构、房间、物资与协同组织治理 |
| 运营分析 | `/analytics`、`/data-dashboard` | 分析模块包 | 报表、数据看板、经营洞察 |
| AI 运营 | `/ai-assistant` | AI 包 / 调用量 | 独立于传统 admin 基础能力收费 |

## 用户影响

- 平台和租户会看到更接近合同与报价单的模块名，而不是仅看到技术端名词。
- 机构养老与居家养老仍保留，但会作为业务模块中的场景分区显示，不再造成顶层导航重复与收费边界不清。
- 未开通模块的租户在导航中不应再看到对应模块；后续页面级应逐步补齐禁用态。
- 中宽屏使用 `更多` 菜单的管理员，需要能通过键盘展开、上下移动、Home/End/PageUp/PageDown 快速定位条目。
- `更多` 菜单需要具备截图级回归保护，避免渐隐提示和滚动表现后续被样式调整破坏。

## 本轮补齐范围

- `更多` 菜单补键盘可达性与当前激活项自动定位。
- Playwright smoke 新增 `更多` 菜单截图级回归。
- 页面级禁用态优先覆盖报警服务、财务服务、通知服务、评定与长护险的主入口页。

## 后续导航回归补面

- scope: 在现有导航结构不变的前提下，把截图级回归从 `更多` 菜单扩展到桌面一级悬浮菜单和移动抽屉。
- affected users: 使用桌面端一级下拉导航的管理员，以及使用手机宽度抽屉导航的管理员。
- changed behavior: 不改变业务导航结构，只增加更完整的视觉回归门禁，确保一级悬浮菜单和移动抽屉在后续样式调整后仍保持可用和可读。
- dependent systems: 顶部导航单一配置源、Playwright smoke、移动抽屉结构、一级菜单 hover 交互。
- verification: nursing-documents `npm run docs:build`；nursing-admin-v2 `npm run lint`、`npm run build`、`npm run test:smoke`。
- rollback: 回退新增截图基线与相关 smoke 断言，不影响导航业务逻辑。

### 范围说明

- 桌面一级悬浮菜单至少覆盖一个含场景分区的业务菜单，用于保护分组标题、菜单项顺序和下拉容器样式。
- 移动抽屉至少覆盖展开后的主面板，用于保护头部、分组按钮和子级入口的整体版式。
- `更多` 菜单、一级悬浮菜单、移动抽屉三者共同构成导航的主回归面。
- 右上角动作区需要纳入同一组回归面，至少覆盖：
  - 已开通通知服务租户下的通知快捷入口与系统设置入口组合样式。
  - 未开通通知服务租户下仅保留系统设置入口的退化布局。
- 顶部身份信息区需要纳入同一组回归面，至少覆盖：
  - 默认管理员下的用户名、租户名、模块数和系统管理员角色标签组合。
  - 机构管理员下的角色标签切换，以及对应身份摘要文案不发生错位或截断。
  - 头像退出登录入口在桌面导航中保持可点击、可回到登录页，不因样式或结构调整失效。

## 验收方向

- 顶部导航的一级分组应可直接映射到可售卖的业务模块。
- 首页应能展示当前租户已开通的业务模块和套餐信息。
- 旧的粗粒度 entitlement 如 `admin`、`billing`、`ai` 仍可被兼容映射，避免联调期一次性破坏后端返回值。
- 未开通模块时，除导航隐藏外，直接访问主入口页也应看到统一的只读禁用态。
- 中宽屏 `更多` 菜单应可滚动、可键盘操作，并受 smoke 与截图断言保护。
- 桌面一级悬浮菜单和移动抽屉应纳入同一组截图级回归，避免后续样式迭代导致导航信息密度、标题层级或可见性退化。
- 右上角动作区在通知入口显示和隐藏两种模式下都应保持可读、对齐稳定，并受 smoke 断言保护。
- 顶部身份信息区在不同角色和租户组合下都应保持稳定，尤其要保护模块数和角色标签的文案切换不引发布局抖动。
- 头像退出登录入口应保持可用，管理员在任意受支持租户下都能从顶部导航稳定回到登录页。

## 回滚

- 若本轮信息架构影响过大，可回退到旧的粗粒度模块模型与场景优先导航。
- entitlement 解释层应保留兼容旧值的映射，以便回滚时无需同步改 backend tenant payload。
