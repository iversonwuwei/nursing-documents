# Admin 共享页面场景上下文扩展

## Scope

- scope: 为 nursing-admin-v2 的共享长护险页面补充显式 scene 上下文，让机构养老与居家养老在复用同一路由时仍保留各自工作台语义。
- affected users: 超级管理员、机构管理员、评定主管、居家评估协同人员。
- changed behavior: `/`、`/operations/daily`、`/elderly/[id]` 现在也会承接或继续透传 `scene=institutional|home`；首页场景入口、日班工作台和老人详情的 CTA 不再把用户带回通用视角。
- dependent systems: nursing-admin-v2 的顶部导航、`/nursing/services` 总览页、上述 5 个共享页、Playwright scene smoke。
- verification: nursing-documents `npm run docs:build`，nursing-admin-v2 `npm run lint`、`npm run build`、聚焦 scene smoke。
- rollback: 回退 scene 查询参数拼装、共享页 scene 分支逻辑、相关文档与 smoke。
- local fallback: 当 `NEXT_PUBLIC_NURSING_WORKFLOW_MODE=bff` 或 `NEXT_PUBLIC_ADMIN_AI_MODE=bff` 但本地 identity / BFF 不可达时，scene 链路页面必须继续保留 demo/mock 可读视图，并用页面级 error signal 暴露“当前已降级”，不能制造未处理 promise 或把整个页面打成空白。

## 目标

- 保持长护险主链路路由唯一，不因为场景分化再次复制导航项。
- 让机构养老入口进入共享页后默认聚焦院内手工建档、自营执行与院内协同。
- 让居家养老入口进入共享页后默认聚焦资料导入、第三方协同、上门派案与居家结算视角。
- 把 scene 作为显式契约沉淀到链接层，而不是依赖用户二次手工筛选。

## 用户影响

- 机构管理员从机构养老或场景总览进入共享页时，会直接看到院内认定与执行语义，不再落到“长护险通用默认页”。
- 居家协同人员从居家养老或场景总览进入共享页时，会直接聚焦资料导入来源、第三方合作排期和护理服务机构协同。
- 长护险业务一级导航仍保留完整通用入口，不强制绑定某一个场景参数。

## 适用页面

| 页面 | 机构养老视角 | 居家养老视角 |
| --- | --- | --- |
| `/elderly/checkin` | 机构评估认定中心，默认展示手工建档个案 | 居家个案评定中心，默认展示资料导入个案 |
| `/staff/tasks` | 院内执行任务台，默认聚焦院内与自有团队任务 | 上门评定回执任务，默认聚焦导入个案与第三方协同任务 |
| `/staff/schedule` | 机构派班排期，聚焦自有团队与院内分派 | 居家派案排期，聚焦第三方合作与上门分派 |
| `/organizations/partners` | 机构定点评估协同，强调评估机构接口 | 居家定点机构协同，强调护理服务机构与上门协作 |
| `/financial` | 机构评定结算与质控，聚焦院内护理结算单 | 居家评定结算与质控，聚焦导入个案和上门评定结算单 |
| `/nursing/checkin` | 机构服务打卡台，聚焦院内自有团队留痕与主管确认 | 居家服务回执台，聚焦第三方协同留痕与异常回执 |
| `/analytics/report` | 机构运营摘要，聚焦院内认定与执行复盘 | 居家监管摘要，聚焦导入个案、上门评定与监管口径 |
| `/` | 首页按机构或居家入口提供不同的优先动作和快捷进入路径 | 首页按机构或居家入口提供不同的优先动作和快捷进入路径 |
| `/operations/daily` | 当班工作台聚焦院内任务、自有团队和院内资源补位 | 当班工作台聚焦居家评定、第三方协同和上门链路 |
| `/elderly/[id]` | 老人详情保持机构视角的返回、AI 与人脸入口 | 老人详情保持居家视角的返回、AI 与人脸入口 |
| `/ai-assistant*` | 保留机构养老上下文继续追踪 | 保留居家养老上下文继续追踪 |

## 场景识别规则

- 评定申请来源：`sourceType === document-import` 视为居家；其他视为机构。
- 协同人员与排期来源：`employmentSource === 第三方合作` 视为居家；其他视为机构。
- 定点机构页面不新增新类型字段，仍基于 `评估机构` 与 `护理服务机构` 组织内容，只调整默认聚焦和 CTA。
- 服务打卡页面基于 `employmentSource` 或责任人所属排期行推断机构/居家视角，不新增额外字段。
- 首页和详情页优先沿用上游链接携带的 `scene`；若未携带，则继续展示通用入口而不是猜测场景。
- AI 入口通过 URL 查询参数继续透传 `scene`，避免从场景页进入 AI 后退回通用视角。
- scene 参数缺失时，页面保持长护险业务通用视角，兼容现有长护险导航入口。
- 本地 BFF 模式下若 `/api/nursing/workflow/board` 或 `/api/ai/*` 因 identity / 下游拒连失败，页面应优先回退到现有 demo/mock 快照；只有写操作仍可维持失败显式提示，不要求静默吞掉。

## 验收方向

- 居家养老总览和模块卡片进入共享页后，标题、说明或默认列表必须能明确体现居家语义。
- 机构养老入口进入共享页后，不应默认落到资料导入、第三方协同或上门语义。
- 顶部导航在 scene 路由下仍能正确显示一级激活态，不因查询参数失焦。
- 从 scene 页面进入 AI 助手后，来源、关注点和场景标签必须继续保留，不能丢失上下文。
- 本地 identity / BFF 不可达时，首页、日班工作台、任务/排期/打卡页与 AI 入口仍需保持可访问，且错误信号应降级为可读文案，不得出现浏览器未处理异常。

## 边界说明

- 本次不新增 API、数据库字段或新路由，只在现有 mock 语义上做场景映射。
- 本次不改长护险业务一级菜单的完整入口集合；scene 只服务于场景入口与共享页默认视图。
- 若未来共享页需要真正不同的数据契约，应再评估是否升级为独立路由或独立 BFF 参数。
