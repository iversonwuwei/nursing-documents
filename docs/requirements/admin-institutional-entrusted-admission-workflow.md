# Admin 机构养老委托入住工作流

## Scope

- scope: 为机构养老补齐“委托来源 + 月度补贴 + 固定服务项目”的入住建档、编辑补录、个案认定和台账工作台。
- affected users: 入住接待、档案专员、护理主管、机构运营。
- entry points:
  - `/elderly/new`
  - `/elderly/[id]/edit`
  - `/elderly/checkin?scene=institutional`
  - `/elderly/entrustment`
- rollout stage: 机构养老 workflow 第二阶段，接入 elder profile 主档真实持久化；前端共享 workflow store 仅保留兼容快照与认定工作台视图。
- validation gates:
  - nursing-documents: `npm run docs:build`
  - nursing-admin-v2: `npm run lint` and `npm run build`
- rollback: 回退 elder profile 的委托字段映射、admin BFF 写代理与 admin 前端对应路由改动，恢复现有入住建档和个案评定字段集。

## Business Requirements

1. 办理入住的老人必须明确委托来源，至少区分为政府委托或企业委托。
2. 每位机构入住老人必须维护固定月补贴金额，作为后续补贴建账和运营核对依据。
3. 每位机构入住老人必须维护固定服务项目集合，作为入住承接和在住服务的基线范围。
4. 在新建入住和编辑老人信息时，用户必须能够录入和修改上述字段。
5. 个案评定中心必须能看到委托、补贴和服务项目摘要，避免认定与后续承接脱节。
6. 系统必须提供一张机构养老工作台，按委托来源和 workflow 状态集中查看委托入住对象。

## User Impact

- 入住建档时，前台或档案专员不再只录基础身份和评估信息，还需要同步确认委托主体、月补贴和固定服务项目。
- 编辑页不再只回写共享 workflow store，而要优先写入 elder profile 主档，再同步 workflow 兼容快照，补录历史老人缺失的委托信息。
- 个案评定页会把委托信息作为认定上下文的一部分，护理主管可以在确认认定前发现补贴或服务项缺口。
- 新工作台会把机构老人分成“待补录委托信息”“待认定确认”“待补贴服务生效”“服务中”几类状态，便于机构运营核对。
- 老人详情页 `/elderly/[id]` 必须能够直接显示主档中的委托类型、委托单位、月补贴和固定服务项，避免工作台与详情页口径不一致。

## Field Requirements

- 委托来源: 必填，值域为 `政府委托`、`企业委托`。
- 委托单位: 必填，记录委托主体名称。
- 月度补贴: 必填，要求为大于 0 的固定金额。
- 固定服务项目: 必填，至少选择 1 项。
- 服务项目先使用前端固定目录，但保存结果必须落入后端 elder profile；后续可平滑切换到后端配置中心。

## Workflow Requirements

1. 机构入住建档
   - 录入基础信息、评估输入、委托来源、月补贴和固定服务项目。
   - 提交后进入机构个案评定中心。
2. 个案认定确认
   - 护理主管查看 AI 建议及委托补贴摘要。
   - 若委托或服务项缺失，不能视为完整承接对象。
3. 委托补贴承接
   - 认定完成后，工作台将对象推进到“待补贴服务生效”或“服务中”。
   - 运营人员可以从工作台追踪当前委托类型、补贴金额和固定服务项目是否齐备。
4. 历史补录
   - 旧老人若没有委托和补贴信息，需通过编辑页补录，并在工作台中落在“待补录委托信息”。
5. 主档回显
   - 新建或编辑成功后，`/elderly/[id]`、个案评定页和机构委托工作台必须看到同一份委托字段。

## UI States

- loading: 表单提交按钮与工作台统计卡片要有明确加载反馈。
- empty: 若机构场景没有委托入住对象，工作台保留建档和认定入口。
- error: 委托来源缺失、月补贴非法、服务项目为空时必须显式提示，不能静默跳过。
- mobile: 新字段区块和服务项目选择不能依赖横向滚动；工作台表格动作需保持可点击。

## Health Signals

- healthy: 新建页提交后，委托信息可在个案评定和工作台中立即看到。
- healthy: 编辑页保存后，历史对象从“待补录委托信息”移出或更新到正确阶段。
- healthy: 长者详情页能够直接显示来自 elder profile 的委托类型、委托单位、月补贴和固定服务项。
- unhealthy: 机构对象仍缺少委托/补贴/服务项字段，或工作台、详情页、编辑页出现数据不一致。

## Rollback

- 回退 `/elderly/new`、`/elderly/[id]/edit`、`/elderly/[id]`、`/elderly/checkin`、`/elderly/entrustment` 以及 elder profile 写链路与共享 workflow store 的兼容映射。
- 若仅工作台回归失败，优先局部回退新路由和入口按钮，不影响已有个案评定主流程。
